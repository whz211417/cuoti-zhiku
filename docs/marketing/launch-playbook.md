# 错题智库个人开发者推广手册

这份手册的目标不是“到处发链接”，而是找到第一批真正有错题整理需求的人，让他们完成一次导入、一次整理和一次复习，再用真实反馈改进产品。

## 先把目标定小

第一轮推广以四周为周期，目标是：

- 10–20 名校园种子用户愿意安装；
- 10 人完成第一次题图或 PDF 导入；
- 5 人提供可复现的产品反馈；
- 3 人连续使用一周；
- GitHub Issue 中形成一份按影响排序的改进清单。

不要把 Star 当成唯一成果。对于本地桌面工具，“有人真的完成学习闭环”比一次曝光更重要。

## 发布前准备

- GitHub Social Preview 使用仓库内的 `docs/assets/social/github-social-preview.png`；源文件可在同目录重新渲染。
- 使用一套完全虚构、无版权风险的演示课程与题目录屏。
- 演示一次完整路径：拖入 → 已保存 → 整理 → 审核 AI 建议 → 今日复习。
- 所有帖子统一指向 [Latest Release](https://github.com/whz211417/cuoti-zhiku/releases/latest)。
- 在说明中主动写明：仅 Windows x64、暂不内置 OCR、首次安装可能出现 SmartScreen 提示。
- 不展示 API Key、Windows 用户名、真实教材、私人题目或本地文件路径。

## 四周启动节奏

| 时间 | 要做的事 | 判断是否继续 |
| --- | --- | --- |
| 第 1 周 | 邀请 10–20 名同学做校园种子用户；只观察首次导入和第一次复习。 | 至少 5 人能独立完成首次导入，否则先修上手流程。 |
| 第 2 周 | 发布一条小红书图文和一条 60–90 秒 B 站演示；只讲一个完整工作流。 | 有真实下载或提问，再继续扩大；不要重复刷屏。 |
| 第 3 周 | 在 V2EX 发布开发复盘，讲本地优先、Tauri、AI 审核和取舍。 | 收集开发者建议与兼容性问题，不与用户争论产品选择。 |
| 第 4 周 | 汇总 Release 下载量、Issue、访谈和一周留存，发布一次真实迭代记录。 | 优先修阻塞使用的问题，再决定是否做英文传播或官网。 |

## 校园种子用户怎么找

优先找有明确场景的人：考研、期末周、FRM/CFA/法考、经济学和数学课程、经常用平板或手机拍题的同学。不要在大群直接丢下载链接，可以一对一发送：

> 我做了一个 Windows 本地错题工具，主要解决题目和答案分开放、整理后不再复习的问题。想找几位同学帮我真实用一周。我不会收集你的题目内容，遇到不好用的地方直接截图告诉我就行。愿意的话我发你 GitHub 下载页。

第一次访谈只问四个问题：

1. 你通常从哪里得到错题？
2. 第一次拖入文件时，哪里让你犹豫？
3. 你是否理解内容已经保存在本机？
4. 第二天你还愿不愿意打开“今日复习”？为什么？

## 小红书图文模板

### 标题备选

- 我把“题目一个文档、答案一个文档”做成了一个 Windows 应用
- 做了一个只把错题存在本机的学习工具，想找人一起测试
- 拖进题图就先保存：我的本地错题整理工作流

### 七张图结构

1. 痛点：题目和答案分开放，复习时找不到上下文。
2. 动作：把题图或 PDF 直接拖进应用。
3. 承诺：原件先保存在本机，再慢慢整理。
4. 整理：题干、作答、答案、解析、错因在同一页。
5. AI：逐字段审核，不自动替你写入。
6. 复习：先答题，再展开答案并安排下次复习。
7. 边界与邀请：Windows、本地优先、暂不内置 OCR，欢迎测试。

### 正文草稿

> 我以前整理错题时，一个文档放题目，另一个文档放答案。录入很慢，真正复习时又经常对应不上。后来我做了“错题智库”：题图、PDF 或讲义拖进去后先保存在电脑上，再把题干、个人作答、答案、解析和错因整理到同一份档案里。AI 可以不用；使用时也只是给逐字段建议，要自己确认才会写入。现在只有 Windows 版，暂时没有 OCR 和云同步。我更想找真正会用一周的人，而不是单纯求点赞。下载和源码都在 GitHub：<https://github.com/whz211417/cuoti-zhiku>

建议标签控制在 3–5 个：`#大学生学习`、`#错题整理`、`#效率工具`、`#开源软件`、`#Windows软件`。

## B 站 60–90 秒演示脚本

| 时间 | 画面 | 旁白 |
| --- | --- | --- |
| 0–8 秒 | 两个分离文档切到应用主界面 | “如果你的错题和答案还分在两个文档里，这个工具就是为这个问题做的。” |
| 8–22 秒 | 从资源管理器拖入一张演示题图 | “题图或 PDF 拖进来，会先保存在本机，不需要先填完整表单。” |
| 22–42 秒 | 打开题目档案，依次展示作答、答案、解析、错因 | “一次学习需要的内容都留在同一份档案里。” |
| 42–58 秒 | 打开 AI 审核浮层，演示采纳一个字段、拒绝一个字段 | “AI 只做建议，而且每个字段都要自己审核。” |
| 58–72 秒 | 今日复习先隐藏答案，再揭示并选择掌握程度 | “整理不是终点，题目会重新回到复习计划。” |
| 72–90 秒 | GitHub Release 页面和边界说明 | “目前只有 Windows 版，数据默认只在本机。项目已开源，欢迎下载试用并告诉我哪里不好用。” |

视频标题可用：`我做了一个本地优先的错题学习应用｜Windows 开源工具`。简介首行放 Latest Release，第二行说明 SmartScreen 与 OCR 边界。

## V2EX 发布稿

标题建议：`[分享创造] 做了一个本地优先的 Windows 错题学习应用，想听听真实使用反馈`

正文结构：

> 我长期用两个文档分别放题目和答案，整理与复习经常脱节，所以做了错题智库。它不是“拍照秒出答案”的产品，核心是原件先保存、题目与解析在同一记录、之后进入间隔复习。
>
> 技术上使用 Tauri 2、React、TypeScript、Rust 和 SQLite。选择本地优先，是因为题目、教材和 API Key 都不适合默认进入云端；AI 只会在用户确认范围后发送本次题目和少量材料片段，结果也必须逐字段审核。
>
> 当前边界也写清楚了：只有 Windows x64、暂不内置 OCR、安装包没有商业 Authenticode 证书。比较希望得到的反馈是首次导入是否顺畅、复习流程是否真的愿意每天打开，以及本地备份是否容易理解。
>
> 仓库与下载：<https://github.com/whz211417/cuoti-zhiku>

发布后集中回复真实问题；不要顶帖、交换 Star 或用多个账号制造热度。

## 每周记录什么

| 指标 | 从哪里看 | 代表什么 |
| --- | --- | --- |
| 独立访客与页面浏览 | GitHub Insights → Traffic | 内容是否带来了真实访问。 |
| Release 页面点击 | 带平台标记的普通链接或手工记录 | 哪个平台带来的访问更有效。 |
| Release 下载量 | GitHub Release 下载量 | 安装意愿，不等于真实使用。 |
| Star 与 Watch | GitHub 仓库 | 对项目的兴趣，不等于留存。 |
| Bug / 功能 Issue | GitHub Issues | 是否形成可行动的反馈。 |
| 首次导入完成率 | 种子用户访谈或自愿反馈 | 上手流程是否阻塞。 |
| 一周后仍使用 | 第 7 天回访 | 产品是否真正进入学习习惯。 |

错题智库不应为了统计而偷偷加入行为分析。早期用 GitHub 公开指标和用户自愿回访已经足够。

## 暂时不要做

- 不要购买虚假 Star、刷下载量或群发私信。
- 不要同时经营五个平台；先把一个演示视频和一篇图文做好。
- 不要用“AI 自动解决一切”作为标题，这与产品实际的可审核设计相反。
- 不要在没有英文安装说明、代码签名和稳定反馈渠道之前急着上 Product Hunt。
- 不要因为有人提出需求就立即加功能；先确认它是否阻塞现有学习闭环。
