# GitHub 展示与推广启动设计

## 目标

把公开仓库从“完整的开发文档入口”提升为“普通学生能快速理解并下载、开发者能快速判断可信度、招聘者能看见产品能力”的产品主页，并提供一套个人开发者可以持续执行的推广方法。

## 受众与成功标准

- 第一受众：使用 Windows、需要整理错题与课程资料的中文大学生。
- 第二受众：关注本地优先、学习工具、Tauri 与 AI 产品设计的开发者和招聘者。
- 首屏应在 30 秒内回答：这是什么、解决什么问题、是否本地保存、在哪里下载。
- 不以虚构用户量、下载量、识别能力或“全自动 AI”换取转化。

## README 信息架构

1. **产品承诺**：标题、简短英文副标题、当前 Windows 下载入口与可信徽章。
2. **真实主视觉**：使用现有 `docs/assets/readme/local-materials.png`，展示本地课程依据与产品设计语言，不生成虚构界面。
3. **为什么值得使用**：围绕“原件先保存”“AI 逐字段审核”“复习与知识网络”三个差异点展开。
4. **完整学习闭环**：用简短流程说明从拖入题图到导出题目册、答案册和 Obsidian 的路径。
5. **真实界面与能力表**：保留经过脱敏的界面截图，减少空状态截图在首屏的权重。
6. **信任与边界**：明确本地优先、API Key 保存位置、OCR 边界、SmartScreen 和备份限制。
7. **用户与开发者分流**：普通用户进入 Release 和安装说明；贡献者进入开发、Issue 和安全策略。

## GitHub 元数据

- 仓库描述保持中文，但更强调“拖入即保存、本地优先、可审核 AI、间隔复习”。
- Homepage 指向最新 Release，减少普通用户寻找安装包的成本。
- 保留已有高相关 Topics，不添加与当前能力不符的 OCR、macOS、mobile 等关键词。

## 推广包

新增 `docs/marketing/launch-playbook.md`，提供：

- 小红书：六至九张图的内容结构和可直接改写的首发文案。
- B 站：60–90 秒演示脚本，以真实工作流录屏为核心。
- V2EX：开发过程与技术取舍型发布稿，不使用营销口吻。
- 校园社群：邀请 10–20 名同学完成真实任务并反馈，而非泛群刷屏。
- GitHub：每次版本发布包含用户可感知变化、安装包、校验值和反馈入口。

## 衡量与节奏

- 每周记录 GitHub `Traffic` 的访客、README 到 Release 的点击、Release 下载量、Star、Issue 与有效反馈。
- 第一阶段目标不是追求大流量，而是获得 10 名真实用户、5 份可复现反馈和 3 名连续使用一周的用户。
- 先在校园与中文学习社区验证，再考虑 Product Hunt、英文 README 或独立官网。

## 安全与真实性约束

- 截图不得出现真实题目、教材、数据库内容、API Key 或个人路径。
- 不替用户自动在社区发帖、私信或刷量；文案由用户确认后自行发布。
- 不承诺尚不存在的 OCR、移动端、云同步或商业代码签名。
- 下载入口只使用 GitHub Latest Release，不把安装包提交到 Git 历史。

## 验收

- README 首屏包含价值主张、主视觉与明确下载入口。
- README 的本地链接、图片、Release 链接和 Issue 链接可验证。
- 推广文档包含可执行的四周节奏、三类平台稿件和指标表。
- GitHub 描述、Homepage 与 Topics 与 README 一致。
- 文档改动通过仓库展示测试、Markdown 链接检查、lint、typecheck 与构建。
