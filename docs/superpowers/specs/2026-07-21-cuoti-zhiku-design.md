# 错题智库 V1 产品与技术设计

## 1. 产品定义

“错题智库”是一款面向中文大学生、以经济学课程为主要场景的 Windows 本地桌面学习应用。它替代“题目文档”和“答案文档”彼此脱节的整理方式，将原件、题干、个人作答、答案、解析、错因、知识点、教材依据与复习记录保存在同一份本地档案中。

V1 的成功标准不是 AI 生成内容的数量，而是用户在断网、未配置 API Key 或 AI 调用失败时，仍能可靠完成收题、整理、检索、复习、备份和导出。AI 是可审核的增强层，不是数据主流程的前置条件。

## 2. V1 范围

### 2.1 必须交付

- 可安装的 Windows 桌面应用，提供正式安装包与卸载入口。
- 课程资料库、待整理收集箱、题目档案和专注复习四条完整本地流程。
- 支持导入 PNG、JPG、JPEG、WEBP 与 PDF；原件在任何识别或 AI 操作之前安全落盘。
- 支持手动录入、编辑和保存题干、个人作答、标准答案、解析、错因、知识点与教材依据。
- 支持阿里云百炼 AI：`qwen3-vl-flash` 为默认模型，`qwen3-vl-plus` 为用户主动触发的深度解析模型。
- AI 输出以字段建议形式进入审核层，用户可以逐字段采纳、编辑或拒绝。
- 教材与讲义保留原件、页码和分段文本，默认使用本地全文检索；用户明确允许后，才发送命中的少量片段。
- 支持四级复习反馈、下次复习日期、复习历史与到期队列。
- 支持分别导出题目册与答案解析册为 PDF，并提供 Markdown 导出。
- 支持自动轮换备份、手动完整资料包导出与资料包恢复。
- 支持系统浅色、深色与跟随系统模式，尊重减少动态效果和减少透明度偏好。

### 2.2 明确不做

- 云同步、账号系统、多人协作、移动端和 Web 版。
- 社区题库、排行榜、连续签到或游戏化积分。
- 无审核的自动覆盖、虚构教材引用或整本教材静默上传。
- 通用聊天机器人、插件市场或多供应商模型路由界面。
- Word 格式高保真导出；V1 只保证 PDF 与 Markdown。

## 3. 技术路线

采用 Tauri 2、React、TypeScript 与 Rust。React 负责高质量桌面界面与阅读排版；Rust 负责文件导入、哈希、SQLite、备份、导出任务和安全凭据。Vite 提供前端构建，Vitest 与 Testing Library 测试前端行为，Rust 单元与集成测试验证数据和文件边界，Playwright 验证关键用户流程。

选择 Tauri 而不是 Electron，是为了降低安装包和常驻内存成本，同时通过明确的命令白名单缩小前端可访问的本地能力。选择 Tauri 而不是 WinUI 3，是为了获得更成熟的阅读排版、PDF 展示和组件测试能力。

系统分为六个清晰边界：

1. `library`：课程、题目、字段、标签和搜索。
2. `ingest`：文件接收、哈希、落盘、重复检测与待整理状态。
3. `materials`：教材原件、页级文本、全文索引和引用定位。
4. `ai`：供应商适配、请求预览、字段建议、用量与失败记录。
5. `review`：复习队列、反馈评分、调度与历史。
6. `portability`：导出、备份、恢复、数据库健康检查与迁移。

模块只通过显式服务接口和稳定数据结构协作；前端不能直接访问数据库或任意文件路径。

## 4. 本地数据与文件系统

应用数据根目录默认位于 Windows Local App Data 下的 `错题智库` 专属目录。用户可以从设置中打开目录和导出完整资料包，但不能在应用运行中随意切换到不受管理的目录。

目录结构：

```text
cuoti-zhiku/
├─ library.sqlite3
├─ originals/
│  └─ ab/cd/<sha256>.<ext>
├─ derived/
│  ├─ previews/
│  ├─ pdf-pages/
│  └─ exports/
├─ backups/
└─ logs/
```

原件采用 SHA-256 内容寻址。导入流程先写入同目录临时文件、同步关闭文件句柄、计算哈希，再原子重命名到最终位置，最后在一个数据库事务中创建附件与待整理记录。若数据库提交失败，原件仍保留在可恢复区；启动健康检查会识别孤立文件并提供恢复入口。

SQLite 开启外键、WAL 和合理的 busy timeout。所有表都包含稳定 UUID、创建时间和更新时间。用户正文不做原地历史覆盖：关键字段保存当前版本，并在 `field_revisions` 中记录变更来源、旧值、新值和时间。

核心实体：

- `courses`：课程名称、学期、颜色与归档状态。
- `problems`：课程、状态、题型、难度、来源和复习状态。
- `problem_fields`：题干、个人作答、答案、解析、错因和备注。
- `knowledge_points` 与关联表：可复用知识点及题目关联。
- `attachments`：原始文件、哈希、MIME、页数和来源名称。
- `materials`、`material_pages`、`material_chunks`：教材、页码、文本和索引。
- `ai_runs`、`ai_suggestions`：请求摘要、模型、用量、状态和字段建议。
- `citations`：教材、页码、片段哈希与引用文本。
- `review_cards`、`review_events`：下次日期、间隔、反馈与历史。
- `jobs`：可恢复的解析、索引、导出和备份任务。

## 5. 关键用户流程

### 5.1 收题

用户可通过工具栏、拖放或粘贴图片进入收集箱。应用立即显示“正在安全保存”，保存完成后出现缩略图、来源文件名和“待整理”状态。无法识别的格式不会创建半成品记录；已保存原件的后续预览或 AI 失败只显示可重试状态。

重复文件不会复制第二份原件，但允许用户选择“关联到现有题目”或“仍创建一条新的待整理记录”。批量 PDF 默认作为一个附件导入；用户在整理时选择页面范围并创建一道或多道题。

### 5.2 整理与题目档案

题目详情采用阅读档案而不是 SaaS 表单：顶部是课程、题号、状态和上下文操作；主体在“原件”和“学习档案”之间形成稳定阅读关系。题干、个人作答、答案、解析、错因、知识点和教材依据以有语义的书页区块呈现，点击后就地编辑。

保存采用短延迟自动保存，并提供明确的“已保存 / 正在保存 / 保存失败”状态。关闭窗口前仍未落盘时必须阻止无提示退出。

### 5.3 AI 审核

用户选择“AI 辅助整理”后，先看到将发送的题图、已有字段和教材片段预览。默认模型为 `qwen3-vl-flash`；“深度解析”才使用 `qwen3-vl-plus`。请求要求返回固定 JSON Schema，包括题干、答案、解析、错因、知识点和引用声明。

响应不会直接写入正式字段，而是生成一组 `ai_suggestions`。每个字段显示原内容、建议内容、采纳、编辑后采纳和拒绝操作。一次审核可只采纳部分字段。AI 未找到教材证据时必须返回空引用；应用只接受能够映射到本地教材、页码和片段哈希的引用。

每次调用记录模型、Token 用量、估算人民币费用和错误类别。设置提供单次警告阈值、每日预算和每月预算；达到硬限制后必须由用户临时解锁。

### 5.4 教材检索

教材导入后立即保存原件，再以后台任务生成页预览和页级文本。能够提取文本的 PDF 直接建立 SQLite FTS5 索引；扫描 PDF 在 V1 中允许用户选择页并通过视觉模型提取，不能在未授权时批量上传整本教材。

检索先使用课程范围、关键词、页码和 FTS5 排名。语义检索属于按需增强：用户启用后，使用百炼 `text-embedding-v4` 为片段生成向量，向量缓存到本地。发送给生成模型的教材上下文默认不超过 5 个片段，并展示教材名与页码。

### 5.5 复习

复习模式隐藏资料库侧栏和答案内容，先呈现题目、必要原件和个人作答区。用户主动展开答案后，纸面式答案、解析、错因和知识点自然向下展开。完成后选择“忘记、困难、熟悉、掌握”四级反馈。

V1 使用确定性的间隔调度：忘记为次日，困难为当前间隔的 1.5 倍，熟悉为 2.5 倍，掌握为 4 倍；新题基准间隔为 1 天，结果取整并设置最大 180 天。算法版本随复习卡保存，未来迁移不会修改既有历史。

### 5.6 导出与恢复

题目册只包含题号、题干、必要原件和可选答题空间。答案解析册按照相同顺序包含答案、解析、错因、知识点和可验证教材引用。导出前提供课程、标签、日期、排序和是否包含原件的筛选。

PDF 由应用内打印文档生成，必须提供分页预览，避免题目标题与正文跨页孤立。Markdown 导出使用相对资源目录。完整资料包包含数据库一致性快照、原件、派生文件清单和版本化 manifest；恢复先解包到临时目录、校验哈希和数据库，再原子替换当前资料库。

## 6. 视觉与交互系统

设计读取为：面向长期学习者的高品质本地知识工具，采用克制、温暖、编辑式的 Apple 邻近语言，而不是营销型玻璃拟态或后台管理面板。

全局设计参数：`DESIGN_VARIANCE = 6`、`MOTION_INTENSITY = 3`、`VISUAL_DENSITY = 4`。

### 6.1 主工作台

采用资料库三栏式：左侧是今日复习、待整理与课程；中栏是所选范围的题目列表；右侧是题目档案。工具栏只保留返回/前进、范围标题、分段导航、搜索、收题和当前上下文操作。避免满屏等权卡片，列表行与阅读页承担主要层级。

### 6.2 阅读与复习

内容区使用温暖中性色背景、适度行宽和稳定垂直节奏。题干与解析选择中文友好的系统字体栈，不下载远程字体。原件像夹入档案的纸张，正文像书页，用户备注像 Notes 的轻量笔记层。深色模式不是简单反色，而是降低纸面亮度并保持图像原貌。

### 6.3 AI 与浮层

AI inspector、设置、确认和短时状态可以使用 Web 近似的 VisionOS 材质：半透明实色、有限模糊、内描边、顶部微高光和多层阴影。它不被称为 Apple 官方 Liquid Glass，也不覆盖整页。`prefers-reduced-transparency` 下禁用模糊并使用不透明背景；`prefers-reduced-motion` 下禁用非必要位移和缩放。

### 6.4 可访问性与效率

- 所有主要流程可通过键盘完成，焦点环清晰可见。
- 文本与图标达到 WCAG AA 对比度；颜色不作为唯一状态信号。
- 拖放始终有等价的文件选择入口。
- 常用快捷键包括收题、搜索、保存、进入复习、显示答案和四级评分。
- 动画只用于解释层级变化，时长控制在 120–240ms。

## 7. 安全、隐私与故障处理

API Key 存入 Windows Credential Manager，数据库和日志不保存明文。网络请求只允许用户配置的百炼 HTTPS 主机；前端不能传入任意 URL。发送前必须显示数据范围，日志只记录请求 ID、模型、用量和错误类型，不记录题目全文或教材片段。

所有后台任务都有 `queued / running / succeeded / failed / cancelled` 状态和重试次数。应用异常退出后，运行中任务恢复为可重试，不自动重复产生费用的 AI 请求。数据库迁移在备份后执行；迁移失败保留旧数据库并进入只读恢复模式。

删除题目先进入应用内废纸篓，30 天后才可永久清理；清理原件前检查引用计数。恢复和覆盖资料库属于高风险操作，必须显示目标、备份状态与不可逆范围。

## 8. 测试与交付门槛

### 8.1 自动化测试

- Rust 单元测试覆盖哈希导入、重复检测、事务回滚、调度、引用校验、资料包 manifest 和路径防护。
- Rust 集成测试使用临时数据目录验证导入、备份、恢复和迁移。
- React 单元测试覆盖自动保存状态、字段建议审核、预算拦截、复习展开和无障碍键盘行为。
- 契约测试使用本地 HTTP 假服务验证百炼兼容请求、JSON Schema、超时、限流和畸形响应，不在测试中消费真实额度。
- Playwright 覆盖“导入图片 → 手动整理 → 模拟 AI 建议 → 局部采纳 → 加入复习 → 导出”主路径。

### 8.2 手工验收

- 断网和无 API Key 下完成全部本地流程。
- 导入 100 张图片与一个 300 页 PDF，界面保持响应并能取消后台任务。
- 模拟磁盘写满、数据库锁定、AI 超时和应用强制退出，验证原件与已保存正文不丢失。
- 在 100%、125%、150% Windows 缩放下检查布局；在浅色、深色、减少动态和减少透明度模式下检查视觉。
- 从空白安装开始完成首次启动、使用、升级、备份恢复和卸载。

### 8.3 发布门槛

发布构建必须通过格式检查、类型检查、全部单元/集成/E2E 测试、Tauri capability 审核和安装包冒烟测试。交付物包括安装包、版本说明、数据目录说明、备份恢复说明和已知限制。未签名测试包必须明确提示；正式公开分发前需要 Windows 代码签名证书。

## 9. 实施切片

实施分为可独立验收的六个切片：

1. 应用壳、设计系统、课程与本地资料库。
2. 原件安全导入、收集箱、题目档案与自动保存。
3. 教材导入、PDF 阅读、FTS5 检索与引用。
4. 百炼配置、请求预览、字段建议审核与预算。
5. 专注复习、调度和历史。
6. PDF/Markdown 导出、备份恢复、安装包与发布验证。

每个切片都必须先写失败测试、实现最小行为、运行完整相关测试，再进入下一个切片。任何 AI 或视觉增强都不能越过本地数据可靠性门槛。
