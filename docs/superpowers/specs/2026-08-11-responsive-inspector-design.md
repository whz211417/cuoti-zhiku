# 响应式 Inspector 修复设计

## 目标

修复“AI 建议审核”和“偏好设置”两个长内容浮层：任何窗口高度下都能滚动到末尾；窗口变窄时内容自动重排，不能横向溢出或遮挡操作。

## 根因

`InspectorSurface` 使用 `liquid-glass-react` 时保留了组件默认的 `24px 32px` 内边距，而应用又按 `100vw - 48px` 计算玻璃宽度，因此真实占用宽度会额外增加 64px。长内容的 `max-height` 和 `overflow` 只放在业务 section 上，外层玻璃仍使用自己的尺寸、裁剪和居中变换，导致滚动区域与视觉容器不一致：正文底部可能被外层裁掉，窄窗口则可能整体超出视口。

## 方案

1. `InspectorSurface` 向玻璃组件传入 `padding="0"`，让应用成为唯一的尺寸与留白来源。
2. 共享 Inspector 容器使用动态视口单位和安全边距限制宽高；业务 dialog 是唯一纵向滚动容器，设置 `overscroll-behavior: contain`，滚轮不会误滚背景页面。
3. AI 审核与偏好设置共用相同的高度约束；标题区在滚动时保持可见，关闭按钮始终可达。
4. 在窄窗口下缩小安全边距和内容内边距；设置项改为单列，AI 模式、资料检索与导出按钮允许换行或占满可用宽度。
5. 保留当前玻璃层级、圆角、弹簧动效与减少透明度 fallback，不增加新依赖。

## 验收条件

- 高度 600px 的窗口中，两个 dialog 的底边不超过视口，并能滚动到最后一个操作或说明。
- 宽度 640px 与 375px 下没有横向滚动；设置编辑器、AI 模式和按钮不被截断。
- 关闭按钮最小点击区域仍为 44×44px，键盘焦点圈和 Escape/Tab 行为不回退。
- `prefers-reduced-motion` 和 `prefers-reduced-transparency` 继续生效。
- 原有 193 项前端测试全部通过，并新增 Inspector 响应式 CSS/组件回归测试。

## 非目标

- 不改变 AI 请求、API Key、课程资料或错题字段逻辑。
- 不把桌面设置改成独立路由或全屏页面。
- 不重新设计现有颜色、字体和导航。
