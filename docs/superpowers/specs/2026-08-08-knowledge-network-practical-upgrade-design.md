# 错题智库 0.3：知识网络与实用升级设计

日期：2026-08-08

## 1. 决策摘要

本轮升级坚持“错题智库是唯一可靠主库，Obsidian 是可选出口”。没有安装 Obsidian 时，收题、整理、课程资料检索、知识图谱、复习、备份和导出仍应完整可用。

按风险与日常价值分三层交付：

1. 数据安全与收题效率：完整资料库备份、剪贴板截图与批量拖放反馈。
2. 学习闭环：应用内课程知识图谱、薄弱知识点与复习摘要。
3. 可选延展：Obsidian 单向导出、可打印题册、共享元素与弹簧动效精修。

暂不实现 Obsidian 双向同步、第三方插件强依赖、AI 自动写入知识关系、扫描 PDF 的静默 OCR，以及未经审核的教材引用。

## 2. 方案比较

### A. 本地主库 + 可选 Obsidian 出口（采用）

知识网络从本地 SQLite 中的已采纳字段生成；应用内提供完整图谱，Obsidian 导出 Markdown、附件和 JSON Canvas。优点是离线可靠、无插件依赖、可恢复；代价是第一版不接受 Obsidian 回写。

### B. Obsidian 作为主库

所有题目直接写入 Vault，通过 Obsidian 管理关系。开发较快，但会把数据完整性、复习调度和附件生命周期交给外部应用，未安装 Obsidian 的用户体验残缺，因此不采用。

### C. 双主库双向同步

SQLite 与 Vault 都可修改，依靠版本和冲突合并保持一致。自由度最高，但重命名、删除、并发编辑和插件 PATCH 会显著增加静默覆盖风险，不适合作为当前版本。

## 3. 信息架构

主侧栏新增“知识网络”，形成五个稳定工作区：学习总览、待整理、今日复习、知识网络、全部档案。课程侧栏继续作为全局筛选器。

知识网络页采用三栏而非满屏卡片：

- 左侧为课程/章节目录和筛选条件；
- 中央为可平移、缩放、聚焦的知识关系图；
- 右侧是所选知识点的阅读式摘要，包含掌握度、关联错题、常见错因、到期复习和教材来源。

节点只来自用户已保存或已采纳的知识点文本。第一版关系固定为“课程包含知识点”和“题目涉及知识点”；未来的“前置、相关、易混淆”关系必须经用户确认后才能持久化。

## 4. 知识图谱数据模型

第一版不要求用户重新整理旧数据。后端从题目 `notes` 字段中抽取已经存在的“知识点：”行，并沿用现有的分隔规则；清洗后按课程内标准化名称合并。每个图谱节点包括：

- `id`：由课程 ID 与标准化名称稳定计算；
- `courseId`、`courseName`；
- `name`；
- `problemCount`、`dueCount`；
- `lastReviewedAt`；
- `masteryScore`：根据现有的复习间隔、最近复习日期和是否到期计算的 0–100 展示值；当前资料库没有保存逐次评分历史，因此不虚构“忘记/困难”次数；
- `mistakeReasons`：来自关联题目的已保存错因；
- `problemIds`：用于打开关联档案。

图谱数据由只读聚合查询生成，不把布局坐标写入学习数据。客户端缓存每门课程的布局；数据变化后重新布局，用户拖动只影响当前会话。这样可避免为了视觉功能迁移或污染核心题目记录。

如果后续需要手工维护知识点别名和关系，再单独增加 `knowledge_points` 与 `knowledge_relations` 表；本轮不提前引入空模型。

## 5. Obsidian 单向导出

用户在设置中选择一个现有 Vault 或 Vault 内目标目录。应用不扫描整个 Vault，只写入专属目录：

```text
错题智库/
  _同步清单.json
  课程名/
    课程概览.md
    课程知识图谱.canvas
    知识点/
      IS-LM 模型.md
    错题/
      problem-稳定ID.md
    附件/
      原始题图或 PDF
```

Markdown 顶部使用简单 YAML 属性，例如 `cuoti_id`、`course_id`、`kind`、`updated_at`、`mastery`；正文使用普通 Markdown 链接，确保脱离 Obsidian 仍可阅读。课程 Canvas 使用 JSON Canvas 1.0，包含课程、知识点和错题文件节点及有向边。

同步规则：

- 应用只管理带有 `cuoti_id` 且记录在 `_同步清单.json` 中的文件；
- 首次导出写入临时目录，全部成功后原子替换本轮管理文件；
- 若目标文件内容校验值与上次导出不一致，视为用户在 Obsidian 中修改过，不直接覆盖；输出带时间戳的冲突副本并提示；
- 不删除清单外文件，不读取 API Key，不导出复习操作日志中的敏感配置；
- “在 Obsidian 打开”使用正确编码的 `obsidian://open?path=...`；找不到 Obsidian 时只提示，不影响导出文件；
- Local REST API 插件仅保留为未来可选高级模式，本轮不依赖。

## 6. 完整备份与恢复

新备份格式为单文件 `.czkbackup` 包，至少包含：

- SQLite 一致性快照；
- `originals` 目录中的题图、PDF 和文本原件；
- `manifest.json`：格式版本、应用版本、创建时间、文件大小和 SHA-256；
- 不包含 Windows 凭据管理器中的 API Key。

创建流程先在应用数据目录的临时位置完成快照和校验，再写入用户目标位置。恢复流程先解包至临时目录、校验清单和 SQLite 完整性、检查相对路径安全，再生成当前资料库救援包，最后替换数据库和原件。任一步失败都保持当前资料库不变。

旧 `.sqlite3` 备份仍可恢复，但设置界面会明确标注其“不含原件”。

## 7. 快速收题

现有窗口级拖放继续保留，并补充：

- `Ctrl+V`：当焦点不在文本输入框时，若剪贴板含图片则直接生成 PNG 原件并进入待整理；
- 多文件拖入显示逐项状态、成功数和失败原因，不用等待全部结束才反馈；
- 当前选中课程作为默认归属；未选课程时进入“未分类”；
- 重复原件继续按 SHA-256 去重，但允许生成新的题目记录并复用附件；
- 所有导入先落盘原件，再创建题目记录。

扫描 PDF OCR 留作后续独立能力。第一版只对可提取文本的 PDF 补充题干候选，不假装识别扫描页。

## 8. 复习增强

今日复习入口显示题量、预计时间和主要薄弱知识点。预计时间使用固定透明规则（例如每题 2 分钟）而不是伪精确模型。

完成一次评分后：

- 当前书页自然收起并过渡到下一题；
- 知识节点掌握度随本地复习记录刷新；
- 会话顶部显示进度与剩余预计时间；
- 会话结束显示题数、掌握分布和下一次最早复习日期。

复习调度算法保持现有规则，本轮只增强可理解性和会话反馈，避免在没有迁移与验证时更换算法。

## 9. 可打印导出

Markdown 题目册和答案解析册继续保留。新增打印友好的 HTML 文稿，内置 A4 分页 CSS、目录、课程分隔、题号和答案分页规则。用户可在系统打印窗口选择“Microsoft Print to PDF”，避免在应用内嵌入无法稳定覆盖中文字体的 PDF 引擎。

界面文案使用“打印 / 存为 PDF”，不会把 HTML 伪称为已生成 PDF。后续若引入嵌入字体与跨平台排版引擎，再增加直接 PDF 文件导出。

## 10. 动效与性能

动效只表达层级与状态：

- 从课程进入图谱、从知识点进入错题，使用共享元素式位置/尺寸过渡；
- 图谱节点选中使用临界阻尼附近的短弹簧，不循环呼吸、不高频闪烁；
- 拖放表面仅在真实拖入时抬升，释放后快速回稳；
- 复习答案以纸页展开，评分后使用方向明确的前进过渡；
- 常规过渡只动画 `transform` 与 `opacity`，大面积 blur 不随帧变化；
- 指针高光保持漫反射形态，不再渲染独立椭圆光斑；
- `prefers-reduced-motion` 下取消位移动画，仅保留即时淡入；
- `prefers-reduced-transparency` 下改为实色表面与清晰边界。

交互目标是稳定 60fps；图谱布局在数据变化时计算一次，指针移动不触发 React 状态更新。

## 11. 错误处理与可恢复性

- 图谱查询失败只影响知识网络页，不阻断档案与复习；
- Obsidian 导出返回成功、部分成功、冲突和失败数量，并保留可读日志；
- 备份和恢复使用阶段性状态，关闭窗口或异常不会留下“看起来成功”的包；
- 写文件只接受经过规范化且位于用户选定目录内的路径，拒绝 `..` 跳转和符号链接逃逸；
- 所有后台任务均可重试，失败不修改原始题目字段；
- AI 不参与备份、图谱聚合或 Obsidian 同步的正确性判断。

## 12. 测试与验收

必须覆盖：

- 知识点解析、去重、课程隔离、掌握度和到期数；
- 空资料库、无知识点课程、大量节点的图谱状态；
- JSON Canvas 结构、稳定 ID、路径清洗、冲突副本和清单更新；
- 完整备份校验、缺失原件、损坏清单、路径穿越、恢复回滚及旧备份兼容；
- 剪贴板无图片、文本框内粘贴、图片粘贴和多文件部分失败；
- 复习进度、失败重试、会话完成摘要；
- 减少动态效果、减少透明度、键盘导航和焦点恢复；
- TypeScript、React、Rust 单元测试、生产构建与 Windows 安装包。

## 13. 发布切分

为降低回归风险，代码按以下顺序完成并验证：

1. 知识图谱只读聚合与页面；
2. Obsidian 文件/Canvas 导出；
3. 完整备份包和兼容恢复；
4. 剪贴板收题和批量反馈；
5. 复习摘要、打印文稿和动效精修；
6. 全量回归、安装包、哈希与升级说明。

每一阶段都必须保持现有本地学习流程可运行，不能用模拟数据填充真实资料库。
